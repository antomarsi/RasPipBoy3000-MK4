# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A pygame-ce recreation of Fallout 4's Pip-Boy 3000 Mk IV, built to run on a Raspberry Pi (GPIO buttons + small display) and also on desktop (keyboard) for development. Currently on branch `rework`, a from-scratch rewrite of an older, now-deleted prototype.

**Architecture-overhaul plan**: all 8 phases are complete. config/`.env` fixes, a JSON save-data store + item catalog, an ECS core (using `esper`), state-based UI widgets, a generic Node registry that replaced the old `BaseModule`/`SubModule` sprite system entirely (that system, along with `core.engine.Entity`/`EntityGroup`, no longer exists in this codebase), a `gpiozero`-based GPIO/input rewire, and the real boot sequence (scrolling text, vault-boy thumbs-up, loading bar). The full phased plan, plus a live follow-up checklist for production content (Phase 8+, one phase per module), is kept in the project owner's local Claude Code plan history, not in this repo. Done so far: STAT → SPECIAL/PERKS/limb-condition-resistances-status-effects with a shared footer (Phases 8/10), INV's per-category item panels + weight/caps footer (Phase 8), DATA → QUESTS' objective list (Phase 9; DATA has no WORKSHOPS tab — dropped, not just deferred), MAP's real GPS+OpenStreetMap rendering (Phase 11), and RADIO's real local-file/YouTube-download playback with a live waveform (Phase 12). Still open: populating the catalogs beyond a handful of example entries each, and MAP/RADIO polish. The Architecture section below describes the current state.

## Commands

```
uv sync                 # install dependencies (first run / after pulling changes)
uv run python main.py   # run the app
```

Pi-only GPIO dependencies are an optional extra once added: `uv sync --extra pi`.

There is no test suite, linter, or CI configured in this repository.

## Architecture

**Entry point**: `main.py` initializes `pg.mixer`, constructs `PipBoy` (`game/pipboy.py`) with `config.SIZE`/`config.OUTPUT_SIZE`, and calls `.run()`. It also sets Pi-specific SDL env vars (framebuffer/touchscreen) when `config.GPIO_AVAILABLE` is true.

**Engine layer** (`core/engine.py`): `Engine` is a thin wrapper around `esper`'s default world. `update(dt)` calls `esper.process(dt)`; `render()` calls `RenderProcessor.process()` then flips the display, skipping the flip entirely on frames where nothing changed (`RenderProcessor.dirty_this_frame`) — a battery optimization for the Pi Zero 2 W target. There is no sprite-group/`Entity` base class anymore; everything is plain esper components on plain entities (`core/components.py`). `core/resource_loader.py`'s `ResourceLoader` is a static, non-instantiable cache-by-key loader for images/sounds/fonts (paths are relative to `config.ASSETS_FOLDER`).

**Rendering pipeline** (`core/processors.py`): `TweenProcessor` (priority 50), `AnimationProcessor` (40), `AutoScrollProcessor` (35), `UIRenderProcessor` (30, in `game/ui.py` — rebuilds a widget's `Renderable.image` from its `*State` component when `Dirty.state >= 1`), then `RenderProcessor` (invoked directly from `Engine.render()`, not an `esper.Processor`) composites every `Active`, visible `(Position, Renderable, Layer)` entity onto the screen in layer order using **additive blending** (`pg.BLEND_RGBA_ADD`) — this matches the app's CRT-glow look and is why any standalone text/image must be pre-flattened onto an opaque background before becoming a `Renderable.image` (see `game/ui.py`'s `render_text` and its docstring) rather than left with a transparent, anti-aliased edge.

**Module tree** (`game/modules/registry.py`): a single recursive `Node` concept (`core/components.py`) replaced the old `BaseModule`/`SubModule` split — a node is a top-level tab, a submodule, or (unused by any real content yet, but supported) a level below that; depth is just how many `Node.parent` links you follow. `NODES: dict[key, entity_id]` and `LABELS: dict[key, str]` index the tree. A node's own entity may carry visual components directly (a leaf with one widget) or own separate entities tagged `OwnedBy(node.key)` (a leaf with several, e.g. `stat.status`'s footer + vault-boy animation + health bars). `switch_node(key)` activates a node and its ancestors (deactivating whatever was active before), remembers each ancestor's `active_child`, and updates the shared Header/SubMenu chrome entities. A node with `background=True` (only `radio`/`radio.stations` today) keeps its `Running` tag after losing `Active`, so a processor gated on `Running` instead of `Active` keeps executing while a different tab is shown — RADIO's actual audio playback (`game/modules/radio/playback.py`) doesn't even use this mechanism, since it's a plain background thread independent of esper entirely; only the visible waveform/footer redraw (`_RadioTickProcessor`) is gated on `Active`, so audio keeps playing regardless of which tab is on screen while the visual redraw correctly stops. `PipBoy.handle_action` dispatches every action via `esper.dispatch_event("action", action)` — but first checks `registry.is_locked()` (true while `boot` is the active top-level) and drops the action entirely if so, so *every* "action" subscriber (navigation, `game/audio.py`'s click sounds, anything added later) is locked out together during boot, not just whichever handler happens to check for it. `registry.handle_action` is the (module-level, so its weak `esper.set_handler` reference stays alive) subscriber, handling `module_*` (switch top-level tab, descending to the remembered leaf), `knob_N` (GPIO's per-position knob buttons: switch directly to child N of the active top-level), `submodule_prev`/`submodule_next` (keyboard Q/E: step to the previous/next child, wrapping around), and `dial_up`/`dial_down` (forwarded to the active leaf's `MenuState`, if it has one). Keyboard bindings (`utils/settings.py`'s `ACTIONS`): `1`-`5` switch top-level tabs, `Q`/`E` cycle submodules, `↑`/`↓` are dial up/down.

Each top-level package (`game/modules/{stat,inv,data,map,radio}/`) exposes a module-level `register(pipboy)`. **These are not called eagerly** — `registry.init_modules()` wraps them as a `tasks: list[(label, callable)]` and hands that list to `boot`, which is the only module whose `register(pipboy, tasks)` takes an extra argument. `boot` isn't in `TOP_LEVEL` (not a navigable tab) — `PipBoy.init_modules()` enters `boot.boot_text` directly unless `config.SKIP_INTRO` (which instead runs every task immediately, then `switch_module(STARTUP_MODULE)` + starts the hum), and the shared Header/SubMenu chrome is hidden while `boot` is the active top-level (`registry._update_chrome`).

Boot has two stages: `boot_text` (Tween-driven scroll + chime) → `loading` (`game/modules/boot/loading.py`). `loading` holds a vault-boy `AnimationState` frozen on frame 0 while its own `_LoadingProcessor` runs one task from the list per frame — real work (each `register(pipboy)` call), not a simulated fill — updating `ProgressBarState.value` and a status-text label from it. Once every task is done it holds for `loading.MIN_DURATION` (UX padding only, since today's placeholder assets load in milliseconds), then unpauses the animation; the animation's `on_complete` calls `switch_module(config.STARTUP_MODULE)` then `game.audio.start_hum()`. Stage transitions use `node_resumed`/`node_paused` handlers and `Tween`/`AnimationState.on_complete` calling `switch_node` directly — no more `BOOT_EVENT` (deleted).

**UI widgets** (`game/ui.py`): `HeaderState`/`SubMenuState`/`FooterState`/`MenuState`/`ProgressBarState` dataclasses plus matching `render_*` pure functions and `UIRenderProcessor`. `FooterState.update_section(index, value)` and `menu_handle_action(state, action)` (`dial_up`/`dial_down`) are the two pieces of behavior still attached to a state object; everything else is a plain redraw. Mutating a `*State` in place does nothing by itself — the mutator must also arm the entity's `Dirty.state = 1`.

**Config** (`utils/settings.py`): a `pydantic-settings` `ConfigSettings` singleton (`config`), instantiated once at import time, `.env`-backed. `SAVE_FILE`, `IDLE_FRAMERATE`, `STARTUP_MODULE` control persistence/battery/boot behavior. GPIO availability is detected via a `try: import gpiozero` cached property (`config.GPIO_AVAILABLE`); `gpiozero`/`lgpio` are the optional `pi` extra (`uv sync --extra pi`), not installed on desktop.

**GPIO/input** (`game/pipboy.py`): `init_gpio_controls()` creates one `gpiozero.Button(pin, pull_up=True, bounce_time=0.05)` per `config.GPIO_ACTIONS` entry (module-switch, knob, and dial pins all in that one dict); `Button.when_pressed` fires on gpiozero's own thread and only ever appends the action string to a plain `collections.deque` (`PipBoy.action_queue`). The main loop drains that queue once per frame on the main thread (`drain_gpio_actions()`), feeding each action into the same `handle_action()`/`esper.dispatch_event("action", ...)` path a keyboard press uses.

**Persistence** (`game/data/store.py`, `game/data/catalog.py`): `save_data: SaveData` (theme, player status, inventory, caps, max_weight, perks, quests, location) loads from `config.SAVE_FILE` (`save/state.json`, gitignored; `save/state.example.json` is the tracked, hand-editable reference) at import time and autosaves every 30s plus on clean exit (`game/pipboy.py`). `catalog.py` loads every `assets/data/*.json` into `dict[baseid, item]` at import time. `theme` (also `game/data/store.py`) holds the RGB-converted draw/tint/bg colors read by `game/ui.py`'s render functions.

**Audio** (`game/audio.py`): `init()` (no-ops if `not config.SOUND_ENABLED`) loads the knob/dial rotary click sounds (`components/sound_click.py`) and subscribes to the `"action"` event so `knob_*`/`dial_*` click. `start_hum()` starts `assets/sounds/UI_PipBoy_Hum_LP.wav` looping (`loops=-1`) once, gated by `config.HUM_ENABLED` — a config-only toggle, no runtime hotkey. `boot.boot_text`'s own chime is loaded/played directly in `game/modules/boot/boot_text.py` instead, since it's tied to that one node's activation.

**Toggles** (`utils/settings.py`): `USE_SCANLINE`/`USE_BLUR` gate whether `PipBoy.init_children()` creates the Scanlines/Overlay entities at all — turning both off is what actually makes the idle-framerate battery throttle reachable, since a perpetually-scrolling Scanlines entity pins `Dirty` at 2 forever otherwise. `HUM_ENABLED` gates `game.audio.start_hum()`.

**MAP** (`game/modules/map/`): real GPS (`game/location.py`, NEO-6M-style over UART via `pyserial`/`pynmea2`, `pi`-extra only) or IP geolocation (`ip-api.com`, the desktop/no-GPS fallback) reverse-geocoded to a city (`geocode.py`, via Nominatim) drives a real OpenStreetMap Overpass fetch (`osm.py`) of that city's roads/buildings/water/POIs, cached to disk **per city** (`save/map_cache/`, refreshed via the API only once the cache ages past `MAP_CACHE_MAX_AGE_S`) so revisiting a city later reuses it instantly. Rendered as vector line art (not raster tiles, which can't be recolored into the theme) into a buffer bigger than the viewport; WASD pans a dead-zone camera across it, recentering (re-rendering from the same cached geometry, no new fetch) once panning nears the buffer's edge — this is what makes "pan across the whole city" work without an infeasibly large buffer. LOCAL renders at a fixed street-level zoom regardless of city size; WORLD renders the whole city at a glance with POIs/roads/buildings simplified (`_WORLD_IMPORTANT_ICONS`/`_MAJOR_HIGHWAYS`) so it isn't noise. A boot task (`make_warm_cache_task`, see `registry.init_modules()`) waits for the first fetch during loading so LOCAL has real data immediately, using the loading task-list's multi-frame convention (a task returning `False` means "call me again next frame" — see `boot/loading.py`).

**RADIO** (`game/modules/radio/`): four bands — STATIONS (curated local files/YouTube downloads from `assets/data/radio_stations.json` + `SaveData.custom_radios`, same shape, user's entry wins on a matching key), TUNER (the FM/AM hardware stub), and a SIGNAL pair split by scope rather than merged into one list: LOCAL SIGNAL is `directory.py`'s online-directory search (`radio-browser.info`, no API key, filtered to verified-working stations via `hidebroken=true`) restricted to the device's own region — `RADIO_ONLINE_COUNTRY` pins that manually, or it's auto-detected from the device's GPS/IP-resolved location by reusing MAP's already-running reverse-geocode (`game/modules/map/geocode.py`'s `get_last_region()` — no second Nominatim call); GLOBAL SIGNAL is the user's own manually configured `"stream"` entries plus the same directory's unfiltered worldwide click-count chart (confirmed by hand to otherwise skew heavily toward a few huge broadcasters if never scoped). Every directory-discovered station carries a `description` naming the country/region it broadcasts from (straight from radio-browser.info's own metadata), shown in RADIO's description panel below the waveform — the same field STATIONS/custom entries use for their own flavor text. `playback.py` is a plain background thread (not tied to esper's `Running`/`Active` at all) that decodes a station via `ffmpeg` piped into `PyAudio` as raw PCM, looping forever — a local file plays directly; a YouTube-sourced station is downloaded once via `yt-dlp` into `save/radio_cache/` and played from that copy from then on; a `"stream"` station (including every online-directory result) plays live and is never cached. A generation counter plus directly killing the live `ffmpeg` subprocess (not just cooperative polling) is what lets `tune()`/`stop()` cleanly interrupt a thread that's normally blocked in a synchronous read. `registry.init_modules()` adds one boot task per not-yet-cached YouTube station (`make_preload_task`) so opening RADIO doesn't hit a download on top of everything else — each reports real fractional progress via yt-dlp's own progress hook, using the loading task list's float-return convention (see `boot/loading.py`) to move the bar smoothly instead of just sitting at "still working". The station `MenuState`'s `on_change` calls `playback.tune()`; a real waveform (from the actual decoded samples, not simulated) renders next to the list, throttled to redraw a few times a second rather than every frame. `LOCAL_RADIO_AVAILABLE` is a stub for real FM/AM tuner hardware this project doesn't have driver specifics for yet — selecting a `source: "tuner"` station just reports that clearly instead of faking playback.
